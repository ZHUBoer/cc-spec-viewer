# 请求规范 (Request Standards)

## 核心 API

统一使用 `zRequest` 发起后端接口请求。

```typescript
import { zRequest } from '@ctrip/xtaro-zx-h5';
```

## 1. 核心规则 (Core Rules)

### 1.1 必须使用 zRequest

- **必须使用 `zRequest` 发起请求**，从 `@ctrip/xtaro-zx-h5` 引入。
- **推荐优先使用 `zRequest`**：更适合复用、集中定义、代码更短更清晰。
- **禁止**直接使用 `fetch/axios`、手写 SOA URL 拼接。

### 1.2 禁止本地缓存接口数据

- **禁止**将后端接口返回的数据缓存到 `localStorage`/`sessionStorage`中复用。
- **必须**每次需要数据时重新调用接口获取最新状态。
- **原因**：H5 营销活动场景简单、生命周期短，一般可以使用内存来做数据复用，数据一致性比性能优化更重要。

### 1.3 必须使用 serviceCode + serviceName 定义接口

接口必须用 **`serviceCode` + `serviceName`** 表达：

```javascript
// ✅ 推荐写法
const getStudentDouyinVouchersInfo = zRequest('31493', 'getStudentDouyinVouchersInfo');

// 🚫 禁止：直接拼 URL
// fetch('/restapi/soa2/31493/json/getStudentDouyinVouchersInfo')
```

### 1.4 禁止手写 head

**调用方不需要也不应该关心 `head`**。`zRequest` 会自动补齐智行通用字段（包括 `data.head.extension` 等）。

```javascript
// ✅ 正确：只传业务参数
await getStudentDouyinVouchersInfo({ productTag: 'xxx' });

// 🚫 禁止：手动构造 head
await getStudentDouyinVouchersInfo({
  head: { ... },  // 严禁
  productTag: 'xxx',
});
```

### 1.5 业务成功判断

统一使用 `res.resultCode === 1` 判断业务成功。

```javascript
const res = await getStudentDouyinVouchersInfo({ productTag: 'xxx' });
if (res?.resultCode === 1) {
  // success
} else {
  throw new Error(res?.resultMessage || '业务失败');
}
```

## 2. 高级用法 (Advanced Usage)

### 2.1 登录前置

需要登录才能调用的接口，使用 `zRequest.withLogin`：

```javascript
const api = zRequest('31493', 'getStudentDouyinVouchersInfo');

export const apiWithLogin = zRequest.withLogin(api, {
  onCancelLogin: (err) => {
    // 用户取消登录：这里兜底 UI/埋点
  },
});
```

> **注意**: 如果用户"取消登录"，内部 Promise 会保持 pending，并通过 `onCancelLogin` 回调通知你。业务侧要在 `onCancelLogin` 做 UI 兜底（例如关闭 loading、提示等）。

### 2.2 请求取消

需要取消上一次请求时，使用 `zRequest.withAbort`：

```javascript
export const apiWithAbort = zRequest.withAbort(api);
// apiWithAbort.abort() 会取消"由该函数发起的上一次请求"
```

> **语义**: `withAbort` 只会取消"由该返回函数发起的上一次请求"。如果需要同时管理多个并发请求，使用 `new zRequest.AbortController()` 统一控制。

### 2.3 可选配置项

```javascript
const getPageInfo = zRequest('31493', 'getPageInfoOn2025TrainNewYear', {
  timeout: 10000,         // 超时时间，单位：毫秒
  withSignature: false,    // 签名扩展，默认关闭
  extension: {             // 业务扩展字段
    from: 'homepage',
  },
});
```

**withSignature 规则**:
- **默认不要开 `withSignature`**，只有当业务明确需要"自动携带订单号签名"等能力时再开启。

## 3. zFetch (少数场景)

`zFetch` 适用于底层封装或已拼好的 URL 路径场景：

```javascript
import { zFetch } from '@ctrip/xtaro-zx-h5';

export function rawFetch(data: any) {
  return zFetch({
    url: '/restapi/soa2/31493/json/getStudentDouyinVouchersInfo',
    method: 'POST',
    data,
    timeout: 10000,
    header: {
      'X-Custom-Header': 'xxx',
    },
  });
}
```

> **场景**: 你正在做更底层的封装（需要直接处理 URL、headers、timeout 等），或者你需要请求一个已经拼好的 /restapi/soa2/... 路径。

## 4. 底层原理 (Background)

### 4.1 自动抹平环境差异

智行 H5 运行在 3 类环境：APP 内 H5、小程序内 H5、普通浏览器 H5。`zRequest/zFetch` 会自动处理这些环境差异，调用方只需要：

- 传 `serviceCode` + `serviceName`
- 传 业务参数 `data`

### 4.2 自动携带的参数

#### data.head.extension (通用扩展字段)

H5 端会自动补齐并透传一组 extension（数组结构：`[{ name, value }]`）：

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `reqTime` | 请求发起时间（秒级时间戳字符串） | |
| `partner` | 标识哪个APP（如 `zhixing` / `tieyou`） | 由域名或 UA 推断 |
| `platform` | 平台（`ios` / `android` / `harmony` / `pc`） | |
| `clientInfo` | 客户端信息摘要 | H5 会从 UA 里提取 |
| `unionId` | 小程序 unionId | 仅小程序环境 |
| `openId` | 小程序 openId | 仅小程序环境 |
| `secretToken` | 小程序 secretToken | 仅小程序环境 |
| `miniType` | 环境类型（`wechat/alipay/baidu/toutiao/browser`） | 仅小程序环境 |
| `packType` | 小程序马甲包类型 | 仅小程序环境 |
| `appid` | APP 或小程序的 appid | 按 `miniType/packType` 推导 |
| `channel` | 渠道 | APP/小程序/浏览器各有不同 |
| `ubtAppId` | 埋点/统计的 appId | 部分环境 |

> **规则**：调用方传入的 `extension` 优先，不会被默认字段覆盖。

#### header (请求头自动补齐)

H5 端会根据场景自动补齐：

- `x-ctx-RmsToken`：浏览器环境下的设备风控指纹 token
- canary 相关 headers：堡垒测试环境时自动带 `x-ctrip-canary-req` / `x-ctx-CanaryReq` / `x-ctx-CanaryIdc`

> **规则**：业务侧一般不需要感知，只要不要手写/覆盖这些字段即可。

## 5. 异常处理 (Error Handling)

### 业务失败 vs 网络失败

| 类型 | 判断条件 | 处理方式 |
| --- | --- | --- |
| 业务失败 | `res.resultCode !== 1` | 推荐抛 Error 或返回统一错误结构 |
| 网络失败/超时 | 进入 `catch` | 超时会被规范化为 `{ code: '-1001', message: '请求超时' }` |

## 6. Agent 常见误区

- **误区**: 手动构造 `head` 或 `extension` 字段。
- **纠正**: `zRequest` 会自动处理，业务层只需传业务参数。

- **误区**: 直接使用 `fetch` 或 `axios` 拼接 SOA URL。
- **纠正**: **必须**使用 `zRequest(serviceCode, serviceName)` 定义接口。

- **误区**: 认为 `resultCode` 不为 1 时接口调用失败了。
- **纠正**: 接口调用成功但业务逻辑失败，需要根据 `resultMessage` 处理。

- **误区**: 将接口返回的数据缓存到 localStorage/sessionStorage 复用。
- **纠正**: H5 营销活动场景简单，每次重新请求最新数据，不做本地缓存。

## 7. Agent 校验清单

- [ ] 是否使用了 `zRequest` 而非 raw fetch/axios？
- [ ] 是否用 `serviceCode` + `serviceName` 定义了接口？
- [ ] 是否移除了参数中的 `head` 字段？
- [ ] 是否使用 `res.resultCode === 1` 判断业务成功？
- [ ] 是否正确处理了 `resultCode !== 1` 的异常分支？
- [ ] 需要登录前置时，是否使用了 `zRequest.withLogin`？
- [ ] 是否**未**开启 `withSignature`（除非明确需要）？
- [ ] 是否**未**将接口数据缓存到本地（localStorage/sessionStorage）？

## 8. 开发步骤

1. 先看后端接口的契约文档：拿到 `serviceCode` 与 `serviceName`
2. **用 `zRequest` 定义接口函数**（从 `@ctrip/xtaro-zx-h5` 引入）
3. 只传业务参数：不要传 `head`
4. **统一用 `res.resultCode === 1` 判断成功**
5. 需要登录前置时：用 `zRequest.withLogin`
6. 需要取消上一次请求时：用 `zRequest.withAbort` 或 `AbortController`
7. **默认不要开 `withSignature`**（除非明确需要）
