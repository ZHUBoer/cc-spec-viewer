# 页面渐进式渲染开发规范 (Progressive Rendering)

## 核心原则 (Core Principles)

1.  **拒绝白屏**: 页面加载时必须立即展示内容（Skeleton 或 静态框架）。
2.  **局部 Loading**: 将 Loading 状态限制在数据依赖的组件内部，**严禁**使用全屏遮罩 Loading。
3.  **动静分离**: 将页面 UI 拆分为“静态无依懒”和“动态强依赖”两部分。
4.  **临界点判断 (Threshold Logic)**: 若静态模块占比极小（如仅一个面包屑）且接口响应极快，允许合并 Loading 状态，避免页面过于细碎。

## 1. 组件分类指南

Agent 在拆解页面组件时，应遵循以下分类：

| 组件类型              | 特征                                        | 渲染策略                     | 示例                                           |
| --------------------- | ------------------------------------------- | ---------------------------- | ---------------------------------------------- |
| **Static Reference**  | 不依赖 API 数据；内容固定或来自 Props；     | **立即渲染** (Always Render) | Page Header, Tab Bar, Background, Static Title |
| **Dynamic Component** | 需等待 API 返回才能展示；包含复杂业务逻辑； | **局部 Loaidng / Skeleton**  | Product List, User Profile, Order Detail       |

## 2. 代码模式 (Code Patterns)

### ✅ 正确示范：骨架屏占位

```jsx
// ❌ 错误：全屏 Loading
// if (loading) return <FullPageLoading />

// ✅ 正确：动静分离
return (
  <div className="page-container">
    {/* 1. 静态部分：立即展示 */}
    <NavBar title="我的订单" />
    <FilterBar />

    {/* 2. 动态部分：局部 Loading */}
    <div className="content-area">
      {loading ? (
        <OrderListSkeleton /> // 骨架屏
      ) : (
        <OrderList data={data} /> // 真实数据
      )}
    </div>

    {/* 3. 底部操作栏：立即展示（如有） */}
    <BottomActions disable={loading} />
  </div>
);
```

## 3. Agent 校验清单

- [ ] 是否存在 `if (loading) return null` 或全屏 Loading？ -> **必须移除**。
- [ ] 页面 Header 是否在 API 请求前就已渲染？
- [ ] 动态列表是否有对应的 Skeleton 组件？
