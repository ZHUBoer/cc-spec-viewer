# 异常处理规范 (Exception Handling)

## 1. 异常分类 (Exception Categories)

前端异常主要分为以下几类，Agent 在处理不同场景时需具备识别能力：

1.  **JS 运行时异常**: 如 `TypeError` (null.xxx), `ReferenceError`。
2.  **异步异常 (Promise)**: `Unhandled Rejection`，需通过 `catch` 捕获。
3.  **网络异常 (Network)**: API 返回 4xx/5xx 或请求超时。
4.  **资源加载异常**: CSS/JS/Image 加载失败（通常由监控 SDK 自动捕获）。

## 2. 核心原则 (Core Principles)

1.  **最小化捕获**: 不要过度使用 `try-catch`。仅在异步操作或不可控的 JSON 解析等场景使用。
2.  **必须抛出 (Must Re-throw)**: 在 H5 环境中，为了确保框架级监控能捕获到异常，**捕获异常后必须再次抛出**。
3.  **用户反馈**: 在抛出前，可以给用户 UI 反馈（如 Toast）。
4.  **禁止自动重试 (No Auto-Retry)**: 调用后端接口时，**网络超时或返回错误不需要重试机制**。让错误自然抛出，由框架监控捕获即可。

## 用法指南 (Guidelines)

### ✅ 正确模式 (Safe Pattern)

```javascript
import { xShowToast } from '@ctrip/xtaro-zx-h5';

async function fetchData() {
    try {
        const res = await api.request(...);
        // 业务逻辑
    } catch (error) {
        // 1. 给用户反馈
        xShowToast({ title: '加载失败，请稍后再试' });

        // 2. [Critical] 再次抛出，让框架/顶层捕获并上报日志
        throw error;
    }
}
```

### ❌ 错误模式 (Anti-Patterns)

#### 1. 吞没异常 (Swallow Error)

禁止捕获后不抛出，这会导致监控系统丢失错误日志。

```javascript
// 🚫 禁止
try {
  ...
} catch (e) {
  console.log(e); // 仅打印日志是不够的
}
```

#### 2. 冗余捕获 (Redundant Catch)

如果不需要特殊 UI 处理，直接让错误冒泡即可，无需 `try-catch`。

```javascript
// 🚫 禁止：毫无意义的捕获
try {
  await api.request();
} catch (e) {
  throw e;
}
```

#### 3. 自动重试机制 (Auto-Retry)

禁止在业务代码中实现接口重试逻辑。网络异常应该让框架监控层统一处理。

```javascript
// 🚫 禁止：自动重试机制
async function fetchDataWithRetry() {
  let retryCount = 0;
  while (retryCount < 3) {
    try {
      return await api.request();
    } catch (e) {
      retryCount++;
      if (retryCount >= 3) {
        throw e;
      }
    }
  }
}
```

## Agent 校验清单

- [ ] 是否避免了空的 `catch` 块？
- [ ] 是否避免了接口重试机制（如 while/for 循环重试、retry 库等）？
