# SpecForge Web 用户使用手册

## 快速开始

### 启动服务

在终端中运行以下命令启动 SpecForge Web 服务：

```bash
npx @ctrip/spec-forge
```

### 登录

如果设置了 `CCV_PASSWORD`，打开浏览器后会进入登录页面，输入密码即可进入。

如果未设置密码，将自动跳转到项目列表页。

## 界面总览

### 项目列表页

登录后首先看到的是项目列表页。这里展示了所有已发现的 Claude Code 项目。

<!-- PLACEHOLDER_IMG: 项目列表页截图 -->

页面结构：
- 左侧：全局侧边栏（可折叠）
- 右侧：项目卡片列表，每个卡片代表一个项目目录

点击任意项目卡片即可进入该项目的会话工作区。

### 会话工作区

会话工作区是你与 AI 交互的主要场所。

<!-- PLACEHOLDER_IMG: 会话工作区全貌截图 -->

工作区由以下部分组成：

1. 顶部标题栏 — 显示会话标题、项目路径、Git 分支、Session ID、运行状态
2. 对话区域 — 展示完整的对话历史，包括用户消息、AI 回复、工具调用等
3. 操作栏 — 位于输入框上方，提供 Git、新建 Change、/opsx:continue 等快捷操作
4. 输入区域 — 底部的消息输入框，支持附件、斜杠命令、文件引用

### 全局侧边栏

全局侧边栏位于界面最左侧，通过图标切换不同面板：

| 图标 | 面板 | 说明 |
|------|------|------|
| 会话列表 | Sessions | 当前项目的所有会话，点击切换 |
| 📖 | Spec Dashboard | 管理 Spec Changes，查看工作流状态 |
| ⚙️ | 设置 | 显示偏好、通知设置 |
| ℹ️ | 系统信息 | 查看系统运行状态 |

点击已展开的面板图标可以折叠侧边栏，再次点击展开。

## 初始化配置

首次进入一个项目时，系统会自动检测配置状态。如果项目尚未初始化 SpecForge 配置，会弹出 Profile 配置弹窗。

<!-- PLACEHOLDER_IMG: Profile 配置弹窗截图 -->

### Profile 配置

Profile 配置弹窗是使用 Spec Coding 的前置步骤，用于告诉 AI 你的项目使用了哪些基建能力。

配置方式有三种：

1. 选择预设 Profile — 如果你的团队已经提供了内置 Profile，直接从下拉列表中选择即可，系统会自动填充所有配置项
2. 表单手动填写 — 逐项填写 MCP 服务、Tool 定义等
3. JSON 导入 — 点击右上角「JSON 导入」，粘贴或上传 JSON 配置文件

### MCP 服务配置

MCP（Model Context Protocol）服务是 AI 获取外部知识的通道。在这里配置你的业务基建 MCP 服务。

每个 MCP 服务需要填写：
- 服务名称（如 `xtaro-zx-library`）
- 连接类型：HTTP / SSE / stdio
- 连接地址（HTTP/SSE 填 URL，stdio 填命令和参数）

点击「添加服务」按钮可以添加多个 MCP 服务。

### MCP Tool 定义

MCP Tool 定义告诉 AI 在什么场景下使用哪些 MCP 工具。分为三类：

| 类别 | 用途 | 使用场景 |
|------|------|---------|
| Overview（全景认知） | 了解框架结构、核心规范 | 任务开始时建立全局上下文 |
| Search（探索发现） | 自然语言检索文档和方案 | 需求模糊或探索实现方案时 |
| Specifications（精准规格） | 查询组件/API 详细文档 | 已确定具体组件名称后 |

每个类别下添加对应的 MCP 工具名称，格式为 `mcp__服务名__工具名`。

### Develop Skills 与代码示例

这两项为可选配置：

- Develop Skills — 填写开发技能的 Git 仓库地址和技能列表，AI 在开发过程中会按需使用
- 代码示例 — 填写项目中最佳实践页面的相对路径，AI 会参考这些代码的编写规范

配置完成后，点击「保存并重新初始化」，系统会将配置注入到项目中。

## Spec Coding 完整流程

Spec Coding 是一套规范驱动的开发流程，将需求从提出到实施分为明确的阶段。整体流程如下：

```
新建 Change → Spec 评审 → Design 评审 → Tasks 评审 → 实施 → 归档
```

<!-- PLACEHOLDER_IMG: Spec Dashboard 侧边栏截图，展示 Changes 列表 -->

### 第一步：新建 Change

有两种方式新建 Change：

**方式一：通过 Spec Dashboard**

1. 在全局侧边栏中点击 📖 图标打开 Spec Dashboard
2. 点击面板右上角的 ➕ 按钮
3. 在弹出的「新建 Change」对话框中填写需求

**方式二：通过操作栏**

在会话工作区的操作栏中，点击「新建 Change」按钮。

<!-- PLACEHOLDER_IMG: 新建 Change 对话框截图 -->

新建 Change 对话框包含：

- 需求内容 — 描述你的业务需求、目标、关键流程，或直接粘贴飞书云文档链接
- D2C 材料（可选） — 如果是前端/全栈需求，勾选「启用 D2C 材料」并填写 Figma 设计稿链接（详见 [D2C 流程](#d2c-前端可视化流程)）

填写完成后点击「发送并创建 Change」，系统会自动创建新会话并启动 Spec 生成。

### 对话中的交互式问答（AskUserQuestion）

在生成 Spec、Design 等阶段产物之前，AI 会在对话中通过交互式问答卡片向你确认关键细节。这是 Spec Coding 流程中非常重要的环节 — AI 不会在信息不充分的情况下直接生成文档，而是先把所有需要你决策的问题问清楚。

<!-- PLACEHOLDER_IMG: AskUserQuestion 交互卡片截图 -->

问答卡片的交互方式：

- 每张卡片包含一个问题和若干选项，点击选项即可回答并自动跳转到下一题
- 如果预设选项都不合适，点击底部的「Something else」输入自定义答案
- 支持键盘操作：`↑` `↓` 导航选项，`Enter` 选择，`Esc` 跳过当前问题
- 多题时右上角显示进度（如 1 of 3），可以前后翻页
- 不确定的问题可以点击「Skip」跳过，AI 会自行判断

回答完所有问题后，AI 才会开始生成对应的阶段产物。

### 第二步：Spec 评审

AI 在对话中完成问答收集后，会生成 Spec 文档。你可以在 Spec Dashboard 中点击对应的 Change 查看。

<!-- PLACEHOLDER_IMG: Spec 评审界面截图 -->

Spec 文档以工作台形式展示，包含：

- 左侧目录导航 — 快速跳转到文档各章节
- 文档正文 — Spec 的完整内容，包括需求分析、方案概述、关键决策等

底部操作区提供两个选择：

| 操作 | 说明 |
|------|------|
| 重新生成 Spec | 将你在文档中添加的意见发送给 AI，重新生成 Spec |
| 确认 Spec 并生成 Design | 确认无误后，系统自动创建新会话生成 Design 文档 |

如果你对 Spec 有修改意见，可以直接在会话输入框中发送你的反馈，或者中止当前任务后补充意见。AI 会根据你的反馈重新调整内容。你也可以在评审界面底部点击「重新生成 Spec」来触发重新生成。

> 💡 在任何阶段，你都可以随时在对话中发送消息来补充意见或纠正方向。

### 第三步：Design 评审

Design 文档的评审流程与 Spec 类似。同样，AI 在生成 Design 之前会先通过对话中的问答卡片确认技术方案的关键决策。

<!-- PLACEHOLDER_IMG: Design 评审界面截图 -->

Design 文档通常包含技术方案、架构设计、流程图（Mermaid 格式自动渲染）等内容。

底部操作区：

| 操作 | 说明 |
|------|------|
| 重新生成 Design | 根据你在会话中补充的意见重新生成 |
| 设计无误，生成任务 | 确认后自动生成 Tasks 任务列表 |

### 第四步：Tasks 评审与实施

Tasks 文档展示了拆分好的实施任务列表。

<!-- PLACEHOLDER_IMG: Tasks 评审界面截图 -->

页面顶部会显示任务进度条（实施阶段）。

底部操作区：

| 操作 | 说明 |
|------|------|
| 重新生成任务 | 复制提示词到剪贴板，在原会话中发送以调整任务 |
| 确认计划并开始实施 | 系统自动创建新会话，启动实施 Agent 执行 `/opsx:apply` |

实施过程中，AI 会逐个完成任务并在 tasks.md 中标记完成状态。你可以在 Tasks 视图中实时查看进度。

### 第五步：归档

所有任务完成后，Tasks 视图底部会显示「归档此 Change」按钮。

点击后系统会创建新会话执行归档操作，将 Change 从活跃列表移至归档列表。

## D2C 前端可视化流程

D2C（Design to Code）是针对前端需求的增强流程，能够根据 Figma 设计稿自动生成页面代码，并提供可视化预览和局部调整能力。

### 启用 D2C 材料

在新建 Change 时，勾选「启用 D2C 材料」复选框。

<!-- PLACEHOLDER_IMG: D2C 材料填写区域截图 -->

每条 D2C 材料需要填写：

| 字段 | 说明 |
|------|------|
| Figma section / node link | 设计稿中对应区域的链接 |
| 关键说明 | 描述这条材料要实现什么、关注哪些交互、涉及哪些场景 |
| 目标范围 | 页面 / 模块 / 组件 |

支持添加多条材料，每条对应一个独立的实现范围。

### D2C Checkpoint 步骤

启用 D2C 后，Spec 确认后会进入 D2C Checkpoint 流程，以步骤条形式展示：

<!-- PLACEHOLDER_IMG: D2C Checkpoint 步骤条截图 -->

| 步骤 | 说明 |
|------|------|
| 1. 确认 Spec | Spec 内容确认无误 |
| 2. 生成静态 UI | AI 根据 Figma 链接生成页面代码 |
| 3. 预览 | 在内嵌预览面板中查看生成效果 |
| 4. 确认 UI 基线 | 确认 UI 效果后锁定基线，进入 Design 阶段 |

每个步骤完成后自动推进到下一步。当前活跃步骤会显示对应的操作按钮。

### D2C 预览面板

点击「预览 D2C 产物」按钮后，右侧会打开预览面板。

<!-- PLACEHOLDER_IMG: D2C 预览面板截图 -->

预览面板包含：

- 左侧产物列表 — 展示所有生成的 D2C 产物，点击切换预览
- 顶部工具栏：
  - 刷新 — 重新同步代码并刷新预览
  - 元素选中 — 开启/关闭元素选择模式
  - 暂存 — 查看和管理暂存的调整指令
  - 预览尺寸 — 切换不同的屏幕宽度（375/393/414/480/600px）
- 预览区域 — 内嵌 iframe 展示实际渲染效果

首次使用时，系统会弹出初始化对话框，自动完成预览工程的创建、依赖安装和服务启动。

### 元素选中与局部调整

D2C 流程允许你直接在预览中选中元素并下达调整指令。

<!-- PLACEHOLDER_IMG: 元素选中模式截图 -->

操作步骤：

1. 点击工具栏中的「元素选中」按钮进入选择模式
2. 在预览画面中点击需要调整的 UI 元素
3. 在弹出的输入框中描述你的调整需求（如「字体改为 14px」「间距增大」「颜色改为 #333」）
4. 选择「发送」直接提交给 AI 执行，或选择「暂存」先收集多条指令

AI 会精确定位到对应的代码位置，仅修改选中元素所在的产物目录内的文件。

### 暂存指令

当你需要一次性提交多处调整时，可以使用暂存功能：

1. 在元素选中模式下，对每个需要调整的元素选择「暂存」
2. 点击工具栏的「暂存」按钮查看所有暂存指令
3. 可以逐条删除不需要的指令，或清空全部
4. 点击「提交暂存」一次性发送所有指令给 AI

<!-- PLACEHOLDER_IMG: 暂存指令对话框截图 -->

## 会话交互

### 发送消息

在底部输入框中输入消息，通过以下方式发送（取决于设置中的发送键配置）：

| 配置 | 发送方式 | 换行方式 |
|------|---------|---------|
| Shift+Enter 发送（默认） | Shift+Enter | Enter |
| Enter 发送 | Enter | Shift+Enter |
| Command+Enter 发送 | Command+Enter | Enter |

输入框支持自动高度调整，最多展示约 5 行内容。

### 中止对话

当 AI 正在执行任务时（顶部显示绿色「Running」状态），你可以随时中止：

<!-- PLACEHOLDER_IMG: 中止按钮截图 -->

点击操作栏中红色的「中止」按钮，AI 会停止当前任务。中止后你可以：

- 在输入框中补充意见或修改指令，然后发送继续
- 切换到其他会话

> 💡 中止不会丢失已完成的工作。AI 已经写入的代码和文件修改会保留。

### 继续对话与恢复会话

会话有三种状态，对应不同的输入框行为：

| 状态 | 输入框按钮 | 说明 |
|------|-----------|------|
| 运行中（Running） | 发送（灰色禁用） | AI 正在工作，等待完成或中止后才能发送 |
| 暂停（Paused） | 发送 | AI 等待你的输入，可以继续对话 |
| 已结束 | 恢复 | 会话已结束，发送消息会恢复会话 |

操作栏中的 `/opsx:continue` 按钮用于驱动 Change 进入下一个阶段（如从 Spec 推进到 Design，或从 Design 推进到 Tasks）。点击后会自动发送阶段推进指令。

### 定时发送

输入框底部可以切换发送模式为「定时发送」：

1. 点击发送模式下拉框，选择「定时发送」
2. 设置发送时间
3. 点击发送按钮

定时消息会在指定时间自动发送。你可以在侧边栏的 Scheduler 标签页中管理定时任务。

### 附件与文件引用

- 附件 — 点击输入框左下角的 📎 按钮，可以上传图片、文档等文件作为消息附件
- 文件引用 — 在输入框中输入 `@` 触发文件路径补全，选择项目中的文件作为上下文引用
- 斜杠命令 — 在输入框中输入 `/` 触发命令补全

### 斜杠命令

输入 `/` 后会弹出命令补全列表，常用命令包括：

| 命令 | 说明 |
|------|------|
| `/opsx:new` | 新建 Change（通常通过 UI 按钮触发，无需手动输入） |
| `/opsx:continue` | 推进 Change 到下一阶段（如 Spec → Design → Tasks） |
| `/opsx:apply` | 开始实施任务 |
| `/opsx:archive` | 归档已完成的 Change |

### 权限审批

当 AI 需要执行敏感操作（如修改文件、运行命令）时，会弹出权限审批对话框。

<!-- PLACEHOLDER_IMG: 权限审批对话框截图 -->

对话框会显示 AI 请求执行的具体操作内容，你可以选择：
- 允许 — 批准本次操作
- 拒绝 — 拒绝本次操作

权限模式可以在设置中调整（详见 [设置](#设置)）。

## 辅助功能

### 全局搜索

按 `⌘K`（或 `Ctrl+K`，取决于设置）打开全局搜索对话框。

<!-- PLACEHOLDER_IMG: 全局搜索对话框截图 -->

支持跨项目、跨会话的全文搜索。输入关键词后，搜索结果会实时展示，点击结果项可以直接跳转到对应的会话和消息位置。

### Git Diff 查看

在会话工作区的操作栏中，点击「Git」按钮打开 Git Diff 对话框。

<!-- PLACEHOLDER_IMG: Git Diff 对话框截图 -->

可以查看当前会话期间 AI 所做的代码变更，以标准 Diff 格式展示。

### 会话导出

点击顶部标题栏中的下载图标 ⬇️，可以将当前会话导出为 HTML 文件，方便离线查看或分享。

### 设置

点击全局侧边栏的 ⚙️ 图标打开设置面板。

<!-- PLACEHOLDER_IMG: 设置面板截图 -->

可配置项包括：

| 设置项 | 说明 |
|--------|------|
| 隐藏无用户消息的会话 | 过滤掉没有用户参与的自动会话 |
| 合并同名会话 | 将标题相同的会话合并显示 |
| 限流自动续发 | 遇到 API 限流时自动安排定时重发 |
| 发送键行为 | 选择 Shift+Enter / Enter / Command+Enter 发送 |
| 搜索快捷键 | 选择 Ctrl+K 或 Command+K |
| 权限模式 | 控制 AI 操作的审批策略 |
| Claude Code 路径 | 手动指定 Claude Code 可执行文件路径 |
| 语言 | 切换界面语言（中文/英文） |
| 主题 | 切换亮色/暗色/跟随系统 |

### 系统信息

点击全局侧边栏的 ℹ️ 图标查看系统运行信息，包括服务版本、运行环境等。

## 常见问题

**Q: 新建 Change 后没有反应？**
A: 请确认已配置 `ANTHROPIC_API_KEY` 环境变量，且 Profile 配置已完成初始化。

**Q: D2C 预览一直加载中？**
A: 首次使用需要初始化预览工程（复制模板、安装依赖、启动服务），请在初始化对话框中点击「确认初始化」并耐心等待。

**Q: 如何在 AI 工作过程中补充意见？**
A: 点击操作栏中的红色「中止」按钮停止 AI，然后在输入框中输入你的补充意见并发送。AI 会基于你的新指令继续工作。

**Q: Spec/Design 的内容不符合预期？**
A: 有两种方式反馈：(1) 在 AI 生成产物前的问答卡片中准确回答问题，确保 AI 充分理解你的意图；(2) 如果产物已经生成但不满意，直接在会话输入框中发送你的修改意见，或中止当前任务后补充意见，AI 会根据你的反馈重新调整。也可以在评审界面底部点击「重新生成」触发重新生成。

**Q: AI 生成产物前的问答卡片可以跳过吗？**
A: 可以。每个问题都可以点击「Skip」或按 `Esc` 跳过，AI 会根据已有信息自行判断。但建议尽量回答，这样生成的产物质量更高。

**Q: 如何查看历史 Change？**
A: 在 Spec Dashboard 面板中，展开「Archived」区段即可查看已归档的 Change。
